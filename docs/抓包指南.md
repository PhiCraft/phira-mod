# 抓一次官方客户端的成绩上传请求（操作指南）

> 目的：拿到官方客户端上传成绩时发的那条 HTTPS 请求，特别是请求体里的
> `token` 字段（就是 `encode_record` 加密出来的 blob）。
> 有了它，我才能判断能不能在开源树里还原出等价的编码。

## 0. 先明确要抓什么

官方客户端上传成绩时发的请求（格式在开源树里是可见的）：

```
POST https://phira.5wyxi.com/play/upload
Content-Type: application/json
Authorization: Bearer <你的登录令牌>        ← 请不要发给我，见第 5 节
{
  "chart": 1234,                 // 谱面 id
  "token": "eJyrVkrLz1eyUjA0MFDSUUrOz0lNzQOKGZqba0FluQC7DgYh",   ← ★ 要的就是这个
  "chartUpdated": "2024-01-01T00:00:00Z"
}
```

**我只要 `token` 那个字符串**（base64）。最好抓**两次**：同一张谱面打两遍、分数不同，
这样一对比就能看出哪些字段在变、blob 大概怎么排布。

---

## 1. 准备（Windows 电脑 + 安卓手机）

1. **电脑装 mitmproxy**（任选一种）
   - `winget install mitmproxy`（推荐）
   - 或去 <https://mitmproxy.org/> 下载 Windows 安装包
   - 装完在命令行确认：`mitmproxy --version`
2. **手机和电脑连同一个 WiFi**（这一步必须）
3. **查电脑的局域网 IP**：`ipconfig`，找 IPv4（例如 `192.168.1.5`）
4. **手机设置代理**：设置 → WLAN → 长按当前网络 → 修改网络 → 高级 → 代理「手动」
   - 主机名：`192.168.1.5`（你的电脑 IP）
   - 端口：`8080`
5. **电脑启动 mitmproxy**：`mitmproxy`（或先用 `mitmweb`，浏览器界面更好点）

## 2. 装证书（决定成败的一步）

安卓：浏览器打开 <http://mitm.it> → 选 Android → 下载证书 → 
设置 → 安全 → 加密与凭据 → 安装证书 → **CA 证书** → 选刚下载的文件。

> ⚠️ 安卓 7 以后，**用户装的证书默认不被 App 信任**（只有浏览器等会信任）。
> 所以先按第 3 节**试一次**：如果抓到 `phira.5wyxi.com` 的明文请求 → 成功，往下走。
> 如果 App 直接连不上/报错、或者 mitmproxy 里只看到 TLS 握手失败 → 
> 说明它不认用户证书，需要第 4 节的方案。

## 3. 试抓（方案 A，最省事）

1. 手机装**官方** Phira 客户端（不是我们的改版），登录你的账号
2. 打开成绩上传（官方客户端里对应的开关）
3. 找一首**官方谱面**（有服务器 id 的，别用本地导入的），难度随意、**建议用低难度**
4. 打完一局 → 看 mitmproxy 里有没有 `phira.5wyxi.com/play/upload`
5. 有 → 右键那条请求 → **Copy → Copy as cURL**，或者直接看 Body 里的 `token`

**再做一次**：同一张谱面再打一遍（分数不同），把第二条也存下来。

## 4. 如果方案 A 抓不到（不认用户证书）

按难度从低到高：

### 方案 B：改官方 APK 让它信任用户证书（**不需要 root**）

思路：给官方 APK 加一个 network security config，声明信任用户证书，重新签名安装。

```powershell
# 1) 解包（需要 apktool）
apktool d Phira-official.apk -o phira-official

# 2) 新建 phira-official/res/xml/network_security_config.xml
#    内容：<network-security-config><base-config cleartextTrafficPermitted="true">
#          <trust-anchors><certificates src="user"/><certificates src="system"/>
#          </trust-anchors></base-config></network-security-config>

# 3) AndroidManifest.xml 的 <application> 上加：
#    android:networkSecurityConfig="@xml/network_security_config"

# 4) 重新打包 + 用 apksigner 签名（debug 密钥即可）
apktool b phira-official -o phira-patched.apk
apksigner sign --ks debug.keystore phira-patched.apk

# 5) 装上去（先卸载官方版；账号数据在服务器上，登录一下就有）
adb install -r phira-patched.apk
```

装好后重复第 3 节。**风险**：改包后签名变了，如果官方客户端校验自身签名会登录失败
（我没见过这种校验，但不能保证）；**建议用小号**。

### 方案 C：root 设备 / 模拟器，把证书装成系统证书

- 有 root（Magisk）：装 `MagiskTrustUserCerts` 模块把用户证书提升为系统证书，最简单
- 或用 AVD 模拟器（`-writable-system` 启动 → `adb remount` → 把证书推进
  `/system/etc/security/cacerts/` → 重启）
  ⚠️ 注意：官方 APK 是 **arm64-v8a**，x86_64 模拟器装不上；需要 arm64 镜像或用真机

### 方案 D：iOS 设备

iOS 上装 mitmproxy 证书更容易被系统信任：
下载证书 → 设置 → 通用 → VPN与设备管理 → 安装描述文件 → 
设置 → 通用 → 关于本机 → 证书信任设置 → **打开完全信任**。
然后在 WiFi 里设置代理指向电脑即可。

## 5. 抓到之后怎么给我（**注意脱敏**）

发我之前请**删掉**这些：
- `Authorization: Bearer ...`（这是你的登录令牌，等于账号密码，**绝对不要发**）
- Cookie、任何设备标识
- 你的账号名/ID（如果不想暴露）

**只需要**：
1. `token` 字段的完整字符串
2. `chart` 字段（谱面 id）
3. 服务器返回的响应（成功还是失败、错误码）
4. 两次上传的话，两份都要（同一张谱面、分数不同）

如果方便，直接用 mitmproxy 存一份 flow 文件也行：
`mitmproxy --save-stream-file capture.mitm`，然后把 flow 里的 token 摘出来给我
（flow 文件里含登录令牌，**别把整个文件发出来**，先自己删掉或只截取那一段）。

---

## 6. 抓到我之后我会做什么

1. 先看长度和熵：判断是「明文/压缩」还是「加密」
   - 若像 zstd/明文结构 → 直接对照 `encode_record` 的 1588 行反汇编还原字段布局，
     实现 `phira/src/upload.rs`，**当天有希望**
   - 若是密文 → 用两次不同分数的密文做差分（找相同前缀/固定长度段 = 可能的 nonce/版本头），
     再决定是否值得继续啃被混淆的 `custom_enc`
2. 结论会写进 `docs/上传成绩逆向笔记.md`

## 7. 必须知道的三个风险

1. **账号风险**：调试期间如果上传了异常成绩，可能被判定异常（协议里写了）。**用小号**。
2. **可能白抓**：如果 `custom_enc` 用的是正经加密 + 内嵌密钥，抓到密文也还原不出来 —— 
   那样这条路的终点就是「静态逆向 `custom_enc`」，而它有可能是死路。
3. **官方随时改格式**：改了就失效。
